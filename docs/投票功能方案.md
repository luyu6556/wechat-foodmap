## 2. 数据模型（新增 3 张表）

### `polls`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text PK | uuid |
| `title` | text notNull | ≤30 字 |
| `note` | text notNull default "" | 可选说明，本期 UI 不暴露（预留） |
| `status` | text notNull default "open" | `open` / `closed` |
| `createdBy` | text notNull | members.id |
| `createdAt` | integer notNull | |
| `closedBy` | text | members.id，结束人（可空） |
| `closedAt` | integer | 结束时间（可空） |

### `poll_options`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `pollId` | text notNull | |
| `placeId` | text notNull | **不写外键约束**，见风险一 |
| `placeName` | text notNull default "" | 发起时的店名快照；地点被删后仍能显示 |
| `placeAddress` / `placeCuisine` | text notNull default "" | 地点被删后的地址与品类快照 |
| `placeAvgPrice` | integer | 地点被删后仍展示发起时人均（重点信息） |
| `placePlatformRating` / `placeAverageRating` | real | 地点被删后的评分快照 |
| `sortOrder` | integer notNull default 0 | 固定展示顺序 |

主键 `(pollId, placeId)`。

### `poll_votes`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `pollId` | text notNull | |
| `placeId` | text notNull | 必须属于该投票的候选 |
| `memberId` | text notNull | |
| `note` | text notNull default "" | 推荐理由，≤140 字 |
| `createdAt` | integer notNull | |
| `updatedAt` | integer notNull | |

主键 `(pollId, memberId)` —— **一名成员在一个投票里只能有一行**，改票走 UPSERT，一人一票由主键天然保证。

### 索引（关键）

```sql
CREATE UNIQUE INDEX polls_single_open ON polls (status) WHERE status = 'open';
```

用 SQLite **部分唯一索引**在**库层面**保证「同时只有一个进行中投票」。

- 已核对项目安装的 Drizzle ORM / Kit 版本：`uniqueIndex(...).where(...)` 能生成 SQLite 部分索引；
  `0003_colorful_rage.sql` 已由生成器产生该 SQL，本地内存 SQLite 验证第二条 `open` 会触发唯一约束。

## 3. 接口

四个 route 文件；写接口用 `memberFromRequest` 取身份，出错统一走 `fail()`。

### 3.1 `GET /api/polls`

返回 `{ open: PollSummary | null, history: PollSummary[], nextCursor: string | null }`。
`history` 每页 20 条，按 `closedAt` 倒序；传 `?cursor=<nextCursor>` 继续取，直到全部可查。

```
PollSummary = {
  id, title, status, createdAt, closedAt, closedByName,
  creatorName, creatorColor,
  totalVotes, optionCount, totalMembers,
  topOptions: [{ placeId, name, count }] // 并列最高票全部返回；零票为空数组
}
```

### 3.1a `GET /api/polls/candidates`

从完整地点库搜索候选，支持 `?q=<店名或地址>&cursor=<游标>`，每页 30 条，返回
`{ places: [{ id, name, address, cuisine, avgPrice, platformRating, averageRating }], nextCursor }`。
发起页不能只复用现有 `/api/places` 的前 500 条，否则旧地点无法入选。

### 3.2 `POST /api/polls`

body：`{ title: string, placeIds: string[], note?: string }`

| 情况 | 响应 |
| --- | --- |
| 无令牌 | 401「请先设置昵称」 |
| 标题为空或 >30 字 | 400 |
| `placeIds` 去重后不在 2～8 家 | 400「候选需要 2 到 8 家」 |
| `placeIds` 含不存在的地点 | 400 |
| 已有 `open` 投票（唯一索引冲突） | **409**「已有进行中的投票，请先结束它」 |
| 成功 | 201 `{ id }` |

写入 `poll_options` 时按传入顺序写 `sortOrder`，并写入店名、地址、人均与评分快照。

### 3.3 `GET /api/polls/[id]`

```
{
  poll: { id, title, status, createdAt, closedAt, closedByName, creatorName, creatorColor },
  options: [{
    placeId, name, address, cuisine, avgPrice, platformRating, averageRating,
    deleted: boolean,
    count, votes: [{ memberId, memberName, memberColor, note, createdAt, mine }]
  }],
  my: { placeId, note } | null,
  totalMembers,
  notVoted: [{ id, name, color }]
}
```

- `options` 严格按 `sortOrder` 返回（**不按票数排序**）。
- `name` / `address` / 人均 / 评分用 `LEFT JOIN places` 取；join 不到时回落到 `poll_options` 快照，
  并把 `deleted` 置 `true`。
- 本期投票页不展示封面（用户补充确认）。进行中人数按现有已注册成员计算，结束后只计结束时已注册成员。
- 不存在 → 404。

### 3.4 `PATCH /api/polls/[id]`

body：`{ status: "closed" }`，**只有这一个合法值**。

- **任何成员都可调用**（见 [PRD 2.1](./投票功能PRD.md)）。
- 已是 `closed` → 409。
- 成功 → `{ ok: true, closedAt, closedBy }`。

### 3.5 `POST /api/polls/[id]/votes`

body：`{ placeId: string | null, note?: string }`

| 情况 | 响应 |
| --- | --- |
| `placeId` 非空 | UPSERT `(pollId, memberId)`，同时校验该 `placeId` 是本投票候选，否则 400 |
| `placeId` 为 null | 删除该成员在此投票的票（撤票） |
| `note` >140 字 | 400 |
| 投票已结束 | **409**「投票已经结束了」 |
| 成功 | `{ ok: true, placeId }` |

### 4.2 新增组件

| 文件 | 职责 |
| --- | --- |
| `components/poll-panel.tsx` | 投票 tab 容器。无进行中 → 空态 +「发起投票」；有进行中 → **直接渲染该投票详情**（少一次点击）；提供「历史投票」入口切换到历史列表 |
| `components/poll-detail.tsx` | 详情：候选列表（固定顺序）、点选 → 展开理由输入 → 提交、结果区（票数条 / 头像 / 理由）、底部「复制结果发到群里」「结束投票」（二次确认）、分享链接 |
| `components/poll-create-dialog.tsx` | 发起：标题（含预置短语快捷键）+ 从完整地点库分页搜索并多选候选（无封面）+ 发布 |

### 4.3 轮询

投票进行中且 `document.visibilityState === "visible"` 时，每 10 秒重拉一次详情；页面隐藏或投票已结束则停止。组件卸载必须清理定时器。

### 4.4 关键交互细节

- 候选顺序固定，**不重排**
- 点选候选后展开理由输入框，按钮文案明确为「投这家」/「改投这家」
- 已投的候选显示选中态 +「我投了这家」
- 结束二次确认文案：「结束后所有人都不能再投，结果会保留在历史里。确定结束？」
- 平票提示：「平票，需要再商量」——**不允许静默挑一家**

## 6. 风险点（必须处理）

### 风险一：`poll_options.place_id` 加外键会**破坏现有的删除地点功能**

若给 `place_id` 加 `REFERENCES places(id)`，删除地点时会被引用约束拒绝，
**现有「作者／群主永久删除地点」会直接失败**——这是新功能弄坏老功能。

**做法**：`poll_options.place_id` **不写外键**；另存店名、地址、人均和评分快照；
详情查询用 `LEFT JOIN places`，join 不到时显示快照信息 + 标注「已从地图删除」，**仍可投，票数照算**。

已登记为[问题汇总](./问题汇总.md) Q22。

### 风险二：「同时只有一个进行中投票」必须由数据库兜住

只在前端隐藏按钮、或在接口里「先查后写」，都存在并发窗口（两人同时点发起会双双成功）。
必须用部分唯一索引 `ON polls(status) WHERE status='open'`，接口捕获唯一约束冲突后统一返回 409。

### 风险三：「实时可见」不是推送

见 [PRD 2.4](./投票功能PRD.md)。不要引入 websocket 或长连接。

### 风险四：深链与昵称弹窗的顺序

`components/profile-dialog.tsx` 在未设昵称时 `onClose` 为 `undefined`，**弹窗无法关闭**。
流程只能是「**先设昵称 → 再落到投票**」，不能让 `?poll=` 抢在昵称设置之前。

### 风险五：不要改已上线的旧迁移

`0000`～`0002` 已在线上库执行过。任何结构补充都必须是新的 `0003` 文件。
