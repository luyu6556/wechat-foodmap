# 开发记录

## 2026-09-29 · 需求与选型

- 接到需求：面向微信群的手机端美食分享地图；重点是现有地点链接迁移、点位识别、照片和群内互动。
- 创建 PRD，并把未确认的访问范围、群数量、真实分享样例列为产品决策。
- 选择服务端持久化方案：结构化记录使用 D1，照片使用 R2；成员昵称和颜色由用户自行设置，设备保存身份凭证。
- 地图与外部链接采用可替换的适配层；外部分享格式不保证都有公开元数据，因此导入流程保留人工确认。
- 建立 Sites 的可部署项目骨架，完成群链接公开访问的设置。

## 2026-09-29 · V1 实现与本地验证

- 接入 D1 与 R2，建立成员、地点、点赞、去过、评分、评论、照片 7 张表。
- 完成手机优先的地图与列表界面、首次昵称/颜色设置、地点添加与详情互动。
- 完成苹果地图坐标和字段识别；解析高德、百度、腾讯常见坐标参数；对大众点评小程序口令给出准确补填提示。
- 完成照片上传、缩略图、详情大图，并加入浏览器端照片压缩以适配移动端和本地预览大小限制。
- TypeScript 检查、构建均通过；Lint 只有动态照片使用普通 `<img>` 的优化提醒。
- 浏览器实测：375px 手机首屏和交互，1280px 桌面并排布局；无横向溢出。
- 实际交互验证：导入用户提供的苹果地图样例，保存地点、点赞、去过、打 5 星和评论后页面状态正确；图片上传接口返回 201，重新打开页面后可显示缩略图和大图。
