# 默认域名受拦截时的替代托管预案

更新：2026-09-30　状态：仅完成本地准备，未创建新账号或部署

## 触发原因

原 Sites 项目部署正常且设置为公开，但用户在电脑微信、手机微信、手机系统浏览器均收到 Cloudflare 拦截页。用户提供 Ray ID `a42c41ab89ede9e5`。手机关闭 VPN／代理并切换蜂窝网络后仍被拦截。这次请求没有到达站点 Worker，页面代码无法处理该拦截。不同域名仍需实测，不能保证换域名一定有效。

## 可选路径

1. **保持现有 Sites，接入自有域名**：代码、D1、R2 和管理入口保留。需要用户已持有可修改 DNS 的域名；用户目前表示没有。Sites 官方支持自有域名，但不代注册。域名接入后仍须在手机微信实测。
2. **迁移到用户自己的 Cloudflare Workers 账号**：使用账号分配的 `workers.dev` 子域名，不需要自有域名。现有 Vinext 构建产物、D1、R2 接口可复用；需要用户开通并登录 Cloudflare 账号、创建 D1 和 R2 资源。新域名同样必须先由用户手机验证可达性。当前本机 Wrangler 未登录任何 Cloudflare 账号。
3. **更换国内托管**：可能更适合微信群，但当前代码依赖 D1／R2，需要重做存储适配。腾讯 CloudBase 默认域名的官方文档仅把它定位为开发测试入口，不适合作为稳定的正式群链接；正式访问仍建议自有域名。

## Cloudflare 迁移准备

已添加 `scripts/prepare-cloudflare-deploy.mjs`。在用户账号可用后：

1. 创建 D1 数据库与 R2 Bucket，记录 D1 UUID、数据库名和 Bucket 名。
2. 运行 `npm run build`；再运行 `node scripts/prepare-cloudflare-deploy.mjs <D1 UUID> <D1 名称> <R2 Bucket 名称> [Worker 名称]`。生成的 `wrangler.personal.json` 被 Git 忽略。
3. 先用 `npx wrangler d1 migrations apply DB --remote --config wrangler.personal.json` 在远端 D1 应用 `drizzle` 目录中的迁移，再执行 `npx wrangler deploy --config wrangler.personal.json`；需要把群主口令哈希设置为 Worker secret。远端命令要在账号登录后确认实际行为与资源名，避免误写原库。
4. 用手机微信和系统浏览器打开新 `workers.dev` 地址，确认首页、添加、照片和管理流程均可用，然后才在群里更换链接。

截至本次排查，Sites 正式 D1 的成员、地点、照片与互动表均为空，因此目前无需迁移用户内容。如果有人开始使用原站点，迁移前必须重新核对和导出数据。
