# 默认域名受拦截时的替代托管预案

更新：2026-09-30　状态：**已选定并发布**，改用 WorkBuddy 站点托管

## 最终结果

新地址 `https://qunliao-food-map.app.workbuddy.host/` 已于 2026-09-30 发布（`deployedAs: http-service`）。该域名解析到腾讯云北京 CLB `49.233.240.214`，属国内 IP，无需自有域名、无需备案、无额外账号。部署方式与平台行为记录见 [开发记录](./开发记录.md) 的「迁移到 WorkBuddy 站点托管并发布」；数据层未改写。

## 触发原因

原 Sites 项目部署正常且设置为公开，但用户在电脑微信、手机微信、手机系统浏览器均收到 Cloudflare 拦截页。用户提供 Ray ID `a42c41ab89ede9e5`。手机关闭 VPN／代理并切换蜂窝网络后仍被拦截。这次请求没有到达站点 Worker，页面代码无法处理该拦截。不同域名仍需实测，不能保证换域名一定有效。

## 可选路径

1. **保持现有 Sites，接入自有域名**：代码、D1、R2 和管理入口保留。需要用户已持有可修改 DNS 的域名；用户目前表示没有。Sites 官方支持自有域名，但不代注册。域名接入后仍须在手机微信实测。
2. **~~迁移到用户自己的 Cloudflare Workers 账号~~（已排除）**：使用账号分配的 `workers.dev` 子域名，不需要自有域名。**该路径不可行**——`workers.dev` 在国内被 DNS 污染：绕过代理直连超时且无 IP，解析得到无关的伪造地址（Dropbox / Twitter 网段），GreatFire 记录其自 2022-05-10 起持续屏蔽。不要把「注册 Cloudflare 账号 + 最小 Worker 连通性测试」列为下一步；只有换成自有域名才可能成立，而用户没有域名。
3. **更换国内托管**：可能更适合微信群，但当前代码依赖 D1／R2，需要重做存储适配。腾讯 CloudBase 默认域名的官方文档仅把它定位为开发测试入口，不适合作为稳定的正式群链接；正式访问仍建议自有域名。
4. **WorkBuddy 站点托管（已采用）**：`*.workbuddy.host` 为国内 IP，无需域名与备案。代价是运行时以 `wrangler dev --local` 承载 Worker 构建，且平台有三条必须绕开的行为（`build/` 目录被剔除、`Authorization` 头被覆盖、增量上传不删文件），详见开发记录。

## Cloudflare 迁移准备（已作废，留档）

以下步骤基于 `workers.dev` 可达这一前提，该前提已被证伪，**不要执行**。`scripts/prepare-cloudflare-deploy.mjs` 仍留在仓库中，但当前发布不经过它。

1. 创建 D1 数据库与 R2 Bucket，记录 D1 UUID、数据库名和 Bucket 名。
2. 运行 `npm run build`；再运行 `node scripts/prepare-cloudflare-deploy.mjs <D1 UUID> <D1 名称> <R2 Bucket 名称> [Worker 名称]`。生成的 `wrangler.personal.json` 被 Git 忽略。
3. 先用 `npx wrangler d1 migrations apply DB --remote --config wrangler.personal.json` 在远端 D1 应用 `drizzle` 目录中的迁移，再执行 `npx wrangler deploy --config wrangler.personal.json`；需要把群主口令哈希设置为 Worker secret。
4. 用手机微信和系统浏览器打开新地址，确认首页、添加、照片和管理流程均可用，然后才在群里更换链接。

原 Sites 正式 D1 的成员、地点、照片与互动表在本次排查时均为空，因此没有用户内容需要迁移。当前发布使用全新状态目录，与原 Sites 数据无关。
